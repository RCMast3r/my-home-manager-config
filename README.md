# home-manager config

One branch, two machines. Everything shared lives at the top level; the
per-machine differences live in `hosts/`.

## Use

```sh
./update.sh                   # build + activate this machine's configuration
./update.sh --update-inputs   # bump flake.lock first
./update.sh --host laptop     # override auto-detection
```

`update.sh` works out which machine it is on before building — `--host`, then
`$HM_HOST`, then a gitignored `.host` file, then the system hostname (matched
as a substring, so `nebs-desktop` finds `desktop`), and failing all of those it
asks once and writes the answer to `.host`.

To build without activating:

```sh
nix build '.#homeConfigurations.desktop.activationPackage'
./result/activate
```

## Layout

| path | what |
| --- | --- |
| `flake.nix` | inputs, and one `homeConfigurations.<host>` per file in `hosts/` |
| `home.nix` | shared home-manager config |
| `packages.nix` | packages installed everywhere |
| `programs.nix` | shared `programs.*` settings |
| `vscode.nix` | the VS Code package both machines run (profile registration, GPU env) |
| `hosts/desktop.nix` | NVIDIA driver pin, CUDA overlay, licence acceptance |
| `hosts/laptop.nix` | integrated graphics, older stateVersion |
| `nvidia-driver-pin.nix` | generated by `update.sh` from the running NVIDIA driver; do not hand-edit |
| `build-foxglove-rpm.sh` | repackages the Foxglove Studio `.deb` as an RPM (Fedora, outside Nix) |

Host files are deliberately thin — a stateVersion, an optional NVIDIA pin, and
any nixpkgs overlays/config that machine needs. Packages are the union of what
the two machines used to install separately, and VS Code (extensions, settings,
keybindings from nix-hm, package from `vscode.nix`) is identical on both; only
the NVIDIA EGL wiring in the wrapper is conditional.

Adding a machine means adding `hosts/<name>.nix` — `flake.nix` maps over the
directory and `update.sh` reads the same list, so nothing else needs touching.

## Graphics on non-NixOS

Both machines use `targets.genericLinux.gpu`, which builds the userspace
drivers and links them into `/run/opengl-driver`. `update.sh` runs the setup
script under `sudo` only when the store path actually changes. The desktop
additionally pins the NVIDIA userspace version to the loaded kernel module.
